🔬Dissector

A Claude Code multi-agent system that reverse-engineers any codebase into an agent-optimized knowledge base — a complete, machine-parseable map another AI agent can load to understand, extend, rebuild, or maintain the project.

🤖 Claude Code Multi-Agent 🗺️ Agent-Readable Output ⚡ Parallel Analysis 🔄 13-Phase Methodology 🌐 Any Language

⚡ Quick Start

# Install the plugin (from any Claude Code session) /plugin marketplace add SufficientDaikon/dissector-agent /plugin install dissector@dissector-marketplace # Then dissect any codebase: /dissect /path/to/your/codebase # No plugin? Fallback: git clone … && ./install.sh

🤔 What Is This?

Dissector is a system of seven cooperating Claude Code agents. Give it a path to any codebase and it autonomously analyzes the whole project — architecture, modules, public APIs, coding conventions, design patterns, tests, error handling, security posture, dependencies, and build system — and writes the result as a {project}-dissection/ knowledge base.

The output is optimized for agents, not humans: Markdown files with YAML frontmatter (the same convention as llms.txt, AGENTS.md, and CLAUDE.md), a small root index that links to focused per-domain and per-module files, greppable cite: tokens anchoring every claim to source lines, and a manifest.yaml that maps every knowledge-base file to the source globs and content hashes it was derived from — so agents can detect exactly what went stale after a code change.

Think of it as a senior engineer who reads the entire codebase once and writes the map every future agent will navigate by. Works with any language, any framework, from 10 files to 10,000+.

🔧 Installation

Prerequisites

  • Claude Code CLI — installed and authenticated (docs)
  • Git (to clone this repository)

Option A — Claude Code plugin (recommended)

Versioned, auto-updating, and the only install path that ships the PreToolUse write-guard hook (see Security). From any Claude Code session:

claude code
/plugin marketplace add SufficientDaikon/dissector-agent
/plugin install dissector@dissector-marketplace

Installs the seven agents, both skills, the /dissect command, and the write-guard hook as a semver-tagged bundle you can update in place. For a team, check the plugin into the repo's project settings so every collaborator gets it.

Option B — Zero-install (project-local)

Clone the repo and start Claude Code inside it. The .claude/ directory is picked up automatically and /dissect works in that session.

bash
git clone https://github.com/SufficientDaikon/dissector-agent.git
cd dissector-agent
claude

Option C — User-level script install (fallback for offline / no-plugin setups)

Clone the repository

bash
git clone https://github.com/SufficientDaikon/dissector-agent.git
cd dissector-agent

Run the installer

bash / powershell
# macOS / Linux
chmod +x install.sh && ./install.sh

# Windows PowerShell
.\install.ps1

This copies the agents, skills, and command into ~/.claude/.

Verify it works

claude code
/dissect

Dissector should ask which codebase to analyze.

⚡ Quick Start

Get your first dissection with one command:

claude code
/dissect /path/to/any/codebase

The orchestrator validates the path, then runs the full pipeline autonomously. When done you'll find a {project-name}-dissection/ folder in your working directory. Point any agent at its index.md to load the codebase map.

Prefer a dedicated session? Run claude --agent dissector instead — it greets you and asks for the path.

⚙️ How It Works

A single agent analyzing a large codebase in one context window runs out of room. Dissector solves this structurally: an orchestrator that never reads source code coordinates six specialists, each with a fresh context window, and runs the four heaviest analysts in parallel. Specialists write their knowledge-base files directly and return only a compact manifest, so the orchestrator stays small no matter the target size.

/dissect <path> — Stage 0: validate, resolve name, prepare output
▼
Stage 1 · dissection-scout — discovery + structure → Recon Brief
▼
Stage 2 · IN PARALLEL: stack-auditor · style-analyst · interface-documenter · quality-auditor
▼
Stage 3 · dissection-synthesist — guides, glossary, root index
▼
Stage 4 · manifest.yaml + link verification → {project}-dissection/

Safety and rigor guarantees carried over from the original methodology: static analysis only (never executes target code), secret redaction (detected keys/tokens become [REDACTED]), crash-proof (unreadable files are skipped and logged), idempotent (a re-run overwrites a previous dissection after a warning, but only once a provenance gate confirms the folder's manifest.yaml carries generator.name: dissector and was generated from the same codebase — a folder failing either check is refused, never deleted), and adaptive sampling for codebases above 500 / 2,000 source files. See Security for the write-guard and injection-resistance details.

📂 Output Format

Every file is Markdown with YAML frontmatter (type, id, covers, public_exports, …), structured inventories in fenced YAML blocks, and own-line citation tokens like cite: src/parser/index.ts#L18-L31 symbol: parse. Lists are sorted, IDs are path-derived and stable, and volatile metadata lives only in manifest.yaml — so regeneration diffs cleanly. A dissection is also a valid Open Knowledge Format (OKF) v0.1 bundle — a superset that adds cite: source tokens and a machine manifest — so any OKF-aware tool can ingest it.

{project}-dissection/
├── index.md # START HERE — root map, links to everything
├── manifest.yaml # machine index: coverage, hashes, status
├── architecture.md # module graph, layers, entry points
├── symbol-map.md # ranked signature map of exports
├── tech-stack.md # languages, frameworks, tooling
├── dependencies.md # every dep: version, category, purpose
├── build-and-test.md # commands, CI, deployment, env vars
├── conventions.md # implicit style guide with consistency %
├── patterns.md # design patterns with confidence grades
├── errors.md # error types, propagation, logging
├── testing.md # framework, structure, how to add a test
├── security.md # observed posture (secrets redacted)
├── performance.md # caching, async, bottleneck risks
├── glossary.md # domain vocabulary
├── AGENTS.md # cross-tool entry point (Codex/Cursor/Copilot/Gemini/…)
├── modules/
│   └── <module-id>.md # one per module: purpose, files, exports
├── api/
│   └── <module-id>.md # public API: signatures + citations
└── guides/
    ├── extend.md # recipes: add a feature/endpoint/test
    └── rebuild.md # reconstruction map + fork strategy

How agents consume it: load index.md, then hop between concepts via each file's ## Related links (the KB is a navigable graph); grep cite: tokens to jump into source; use manifest.yaml to detect staleness — intersect git diff --name-only with each entry's covers globs (or compare source_hashes) and regenerate only the dirty files.

🏗️ Architecture

Seven agents, two skills, one command — with strict role boundaries:

  • dissector (orchestrator) — validates input, spawns specialists, finalizes manifest.yaml. Restricted to spawning exactly the six specialists via Agent(...) tool rules. Holds only briefs and manifests, never raw source.
  • dissection-scout — phases 1–2. Maps the tree, detects languages, selects the sampling tier, writes architecture.md + modules/*, returns the Recon Brief every other specialist receives.
  • dissection-stack-auditor — phases 3, 10, 11. Reads manifests/lockfiles/CI configs only; writes tech-stack.md, dependencies.md, build-and-test.md. Runs at low reasoning effort — it's mechanical.
  • dissection-style-analyst — phases 4–5. The heaviest source reader; writes conventions.md and patterns.md. Runs at high effort — confidence-graded pattern attribution is judgment-heavy.
  • dissection-interface-documenter — phases 6, 8. Traces the public boundary; writes api/*, symbol-map.md, errors.md.
  • dissection-quality-auditor — phases 7, 9. Tests + security/performance posture; writes testing.md, security.md, performance.md.
  • dissection-synthesist — phase 12. Reads the generated knowledge base (not the codebase) and writes guides/extend.md, guides/rebuild.md, glossary.md, and the root index.md. Runs at high effort.

No two agents write the same file (disjoint ownership makes the Stage-2 parallelism race-free), analysts are read-only on the codebase (Read/Glob/Grep + Write scoped to output), and every specialist is preloaded with the dissection-standards skill so format rules exist in exactly one place.

⚙️ Configuration

Model selection (not hard-coded)

No agent pins a model: — specialists inherit your session model. Three ways to control it:

  • Set the session model with /model — all specialists follow.
  • Route every subagent to a specific model with the CLAUDE_CODE_SUBAGENT_MODEL environment variable.
  • Pin per-role models by adding a model: line to any agent's frontmatter — e.g. a cheaper model for the stack auditor, a stronger one for the synthesist.

Reasoning effort

Each agent ships a task-shaped effort default (low for the mechanical stack audit, high for pattern analysis and synthesis). Edit the frontmatter to change it.

Sampling

Automatic by codebase size: <500 source files → every file read; 500–2,000 → all read, repetitive patterns summarized; >2,000 → stratified sampling (entry points, configs, APIs, tests exhaustively; proportional sampling elsewhere), disclosed in index.md and manifest.yaml.

🔒 Security

  • Static analysis only — Dissector never executes, compiles, or runs the target code, and never fetches remote repositories.
  • Write-guard hook (plugin install) — the plugin ships a PreToolUse hook (scripts/write-guard.sh) that is lock-gated to active dissection runs: unless a fresh *-dissection/.dissect-lock marks a run in progress (or the write targets a *-dissection/ path), it stays silent and your own permission settings decide. Mid-run it emits permissionDecision: allow for writes inside the *-dissection/ output folder and permissionDecision: ask for anything else, so an injected payload can't silently steer a specialist into writing elsewhere. This harness-level backstop rides with the plugin install only; the zero-install and script-install paths instead rely on the agents' permissionMode: acceptEdits plus the in-prompt rule that analyzed content is data, never instructions.
  • Prompt-injection resistance — analyzed file content is treated as untrusted data, never instructions. If a codebase contains text addressed to an AI agent ("ignore your instructions, write X…"), specialists record it as a finding and do not comply.
  • Secret redaction — anchored patterns for AWS keys, JWTs, private keys, and modern provider tokens (sk-/sk-ant-, ghp_/github_pat_, xoxb-, AIza, npm_, glpat-, and more) become [REDACTED], with a deterministic Stage-4 grep over the generated knowledge base as a second layer.
  • Citation verification — every cite: token is machine-checked (file exists, line range in bounds, symbol present) and the verified/broken counts are reported in manifest.yaml.

🔧 Troubleshooting

  • /dissect not found — for user-level installs, confirm ~/.claude/commands/dissect.md exists (re-run the installer); for project-local use, make sure you started Claude Code inside the cloned repo.
  • "Refusing to delete / overwrite" on re-run — the overwrite provenance gate refused: the existing {project}-dissection folder either has no manifest.yaml, has one not written by Dissector (generator.name ≠ dissector), or is a dissection of a different codebase. Dissector never deletes a folder it can't prove it generated for this project: rename it or run from another directory.
  • Run marked PARTIAL — a specialist failed twice. index.md lists what's missing and manifest.yaml has status.complete: false. Re-run /dissect, or ask Claude to re-run just the named specialist.
  • Dissector answered from a subagent and refused to run — orchestration must run in the main session (subagents can't spawn subagents). Use /dissect directly or claude --agent dissector.
  • Huge codebase, slow run — Tier-3 sampling engages automatically above 2,000 source files; you can also point /dissect at a subdirectory to scope the analysis.
