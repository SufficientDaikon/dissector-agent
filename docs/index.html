🔬Dissector Agent

A GitHub Copilot CLI agent that reverse-engineers any codebase into comprehensive, organized documentation through 13 systematic analysis phases. Point it at a codebase — get 17+ interlinked markdown documents.

🤔 What Is This?

The Dissector Agent is a custom agent for GitHub Copilot CLI. When you install it, you get a new @dissector command in your Copilot Chat panel. Give it a path to any codebase, and it will autonomously analyze every source file — producing a complete documentation folder that covers architecture, design patterns, coding conventions, API references, testing strategies, security practices, build systems, and more.

Think of it as a senior engineer who reads your entire codebase and writes the documentation that should exist. It works with any programming language, any framework, any project size — from 10 files to 10,000+.

What Makes It Different?

🤖

Fully Autonomous

Give it a path and walk away. It runs 13 phases without asking questions, producing complete output.

📎

Code Citations

Every claim is backed by an exact file path and line number. No hallucinated descriptions — real code evidence.

🛡️

Secret Redaction

Automatically detects API keys, tokens, and passwords. Replaces them with [REDACTED] in all output.

📏

Scales Gracefully

Auto-selects sampling strategy: exhaustive for small, stratified for large codebases. No config needed.

🔁

Idempotent

Safe to re-run. Detects previous dissections and overwrites them. Non-dissection folders are never touched.

🌐

Any Language

35+ language extensions recognized. Polyglot codebases get per-language analysis sections.

⚙️ How It Works

👤 You invoke @dissector Provide a codebase path
🔬 Dissector Agent Validates path → resolves project name → runs 13 phases
📂 File System Tools glob · grep · read · create · powershell
📝 Dissection Folder 17+ interlinked markdown documents

Key Design Principles

  • Static analysis only — the agent never executes, compiles, or runs your code
  • Autonomous execution — once started, it runs all phases without user interaction
  • Resilient — unreadable files, encoding errors, and binary files are skipped gracefully
  • Honest — documents what IS, not what should be; notes discrepancies between documented conventions and actual code
  • Every claim is cited — code excerpts include exact file path and line numbers

🟢 Getting Started

Getting Started

Dissect a local project

Point the agent at any directory containing source code. It resolves the project name automatically from package.json, Cargo.toml, pyproject.toml, or the directory name.

@dissector Dissect C:\Users\dev\projects\my-express-api Click to copy
Expected result: A "my-express-api dissection" folder with 17+ markdown documents covering the entire codebase.
Getting Started

Dissect the current workspace

If you already have a project open in VS Code, you don't need to specify a path — the agent uses the workspace root.

@dissector Analyze this codebase Click to copy
Expected result: The agent detects the workspace root and produces a dissection folder in the working directory.
Getting Started

Dissect a subdirectory

For monorepos, you can point the agent at a specific package or service directory.

@dissector Reverse-engineer the backend: /home/user/monorepo/packages/api Click to copy
Expected result: The agent scopes analysis to only packages/api and produces an "api dissection" folder.

🔴 Troubleshooting

Troubleshooting

Path doesn't exist error

If you get a "path does not exist" error, make sure you're providing the correct absolute path.

@dissector Dissect C:\exact\path\to\my\project Click to copy
Fix: Use an absolute path. On Windows, use backslashes. On macOS/Linux, use forward slashes.
Troubleshooting

Partial output / context exhaustion

Very large codebases (5000+ files) may exhaust the context window. The agent writes what it has and marks the output as partial.

@dissector Dissect ~/repos/very-large-project Click to copy
Fix: Re-run the dissector on the same path. It's idempotent — it will overwrite the partial output with a fresh attempt.

⚙️ Configuration

Model Selection

The agent uses claude-opus-4.6 by default for maximum analysis quality. To change it, edit the YAML frontmatter:

yaml
---
model: claude-opus-4.6  # Change to claude-sonnet-4 for faster analysis
---
ModelSpeedQualityBest For
claude-opus-4.6SlowerHighestThorough analysis, large codebases
claude-sonnet-4FasterHighQuick dissections, smaller codebases

Automatic Sampling

The agent auto-selects sampling based on file count. No configuration needed:

Source FilesStrategyCoverage
< 500Exhaustive100% of files
500–2,000Full + Summarize100% analyzed, patterns summarized
> 2,000Stratified Sampling100% structural + 15% per module

🔧 Troubleshooting

Agent not found when typing @dissector

Cause: The agent file is not in the correct directory.

powershell
# Windows — verify the file exists
Test-Path "$env:USERPROFILE\.copilot\agents\dissector.agent.md"

# macOS/Linux
test -f ~/.copilot/agents/dissector.agent.md && echo "Found" || echo "Not found"

If not found, re-run the installer.

Dissection takes a very long time

Cause: Large codebases (2000+ files) require extensive analysis.

Fix: The agent auto-uses stratified sampling. For faster results, change the model to claude-sonnet-4.

Context window exhaustion / Partial output

Cause: Very large codebases may exhaust the LLM context.

Fix: Re-run the agent. It's idempotent — it overwrites partial output.

Output folder "already exists" error

Cause: A folder exists with the expected name but wasn't created by the dissector.

Fix: Rename or move the conflicting folder, then re-run.
